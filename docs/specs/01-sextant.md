# Spec：Sextant 金融工具站

> 状态：ready-for-agent（下一步用 `/to-tickets` 按产品拆票）

## Problem Statement

开源项目 [`jerbouma/financetoolkit`](https://github.com/JerBouma/FinanceToolkit) 是一个 Python 库：几百个财务比率、风险、绩效、期权、宏观指标，但只能写代码调用，没有界面，普通人用不了，也没法拿来展示。

我想以它为参考，做一个能真正使用、能公开展示的产品。目标不是 1:1 复刻原版，原版只是参考材料；判断标准是"能跑、能用"。

现实约束：
- 访客打开就要能用，不能先填 API key。
- 行情价格没有任何免费数据源允许公开展示（2026-11-22 调研：Tiingo、Alpha Vantage、Twelve Data、EODHD、FMP、yfinance、Polygon 免费档都禁止对外展示或再分发；Finnhub 连衍生结果都禁止分享）。
- 可以合法公开展示的免费数据：SEC EDGAR（财报）、FRED 公共领域序列、US Treasury、World Bank、ECB（宏观）、Frankfurter（汇率）。
- 以后要多用户（Google 登录），AI 调用和用户数据必须按用户隔离和计量。

## Solution

建一个公开的金融工具站 **Sextant**（独立 public 仓库 `sextant`），一个站点、统一登录、共享后台，里面有 8 个从用户角度看彼此独立的工具，每个工具至少一个核心用户功能：

| # | 工具 | 用户做什么 | 数据 | 原版参考 |
|---|---|---|---|---|
| P6 | Options Calculator | 填参数看 BS 价格、Greeks、隐含波动率、payoff 图 | 无需数据 | options |
| P3 | Risk & Performance | 选几只标的和基准，看波动、回撤、VaR/CVaR、Sharpe/Sortino、Beta、技术指标 | 合成数据 / 用户自带 key | risk、performance、technicals、econometrics |
| P4 | My Portfolio | 填持仓或导入交易，看持仓、盈亏、vs 基准、组合风险 | 合成数据 / 用户自带 key；FX 用 Frankfurter | portfolio |
| P1 | Company Health Check | 输入 ticker，看五类比率、Altman Z、Piotroski F、多公司对比 | SEC EDGAR | ratios、models |
| P2 | Valuation Calculator | 输入 ticker，调 DCF/WACC 假设，看内在价值和敏感性 | SEC EDGAR | models/valuation |
| P5 | Macro Dashboard | 看 GDP、CPI、利率、失业、收益率曲线，跨国对比 | FRED、Treasury、World Bank、ECB | economics、fixedincome |
| P7 | Screener & Calendar | 按基本面筛股，看财报和分红日历、最新 SEC 申报 | SEC EDGAR | discovery |
| P8 | AI Analyst | 用自然语言提问，AI 调用各工具的计算结果作答，数字可追溯 | 以上全部 | MCP 层 + FinRobot 模式 |

访客无需登录就能用全部工具。行情类工具默认使用标明"演示数据"的合成行情；登录用户可以填自己的 Tiingo 或 FMP key，用真实数据计算。每个工具二期加"AI 解读"按钮（需登录、按天限额）。

开发顺序：P6 → P3 → P4 → P1 → P2 → P5 → P7 → P8。每个工具先做 MVP 上线，再做完整版。

## User Stories

### 站点与通用

1. 作为访客，我想打开 Sextant 首页就看到 8 个工具的入口和一句话说明，以便马上知道这里能做什么。
2. 作为访客，我想不登录就能使用所有工具的基本功能，以便零门槛试用。
3. 作为访客，我想在顶部导航里随时切换到另一个工具，以便在工具之间来回跳转。
4. 作为访客，我想每个工具的输入框都预填一组合理的默认值，以便第一次打开就能直接看到结果。
5. 作为访客，我想在每个页面底部看到"Not investment advice"免责声明和数据来源署名，以便知道数据从哪来、结论不构成投资建议。
6. 作为访客，我想在使用演示数据时，页面上有醒目的"Demo data"标记，以便不把合成数据误当成真实行情。
7. 作为访客，我想每个指标旁边都有一个简短说明（是什么、怎么算、怎么读），以便看懂结果。
8. 作为访客，我想图表可以悬停查看具体数值，以便读出精确的数字。
9. 作为访客，我想把结果表格导出成 CSV，以便自己再加工。
10. 作为访客，我想把当前的输入参数编码进 URL，以便把这次分析分享给别人，对方打开看到同样的结果。
11. 作为访客，我想在手机上也能正常查看结果，以便随时打开。
12. 作为访客，我想在输入无效（比如 ticker 不存在、日期反了）时看到明确的错误提示，而不是空白页面，以便知道该怎么改。
13. 作为访客，我想在某个指标因数据缺失算不出来时，看到"缺少哪项数据"的说明，而不是整个页面报错，以便其他指标照样能看。
14. 作为访客，我想界面是英文的，以便用标准金融术语阅读。
15. 作为用户，我想用 Google 账号登录，以便保存我的组合、key 和设置。
16. 作为登录用户，我想随时退出登录并删除我的账号和全部数据，以便掌控自己的数据。

### 数据与自带 key

17. 作为登录用户，我想在设置页填入自己的 Tiingo 或 FMP API key，以便行情类工具用真实数据计算。
18. 作为登录用户，我想在填 key 时立即验证它是否有效，以便及早发现填错。
19. 作为登录用户，我想我的 key 加密保存在服务端，以便换设备不用重填，同时不被泄露。
20. 作为登录用户，我想随时替换或删除我的 key，以便停用真实数据。
21. 作为登录用户，我想在工具里切换"Demo data / My data"，以便在演示数据和真实数据之间对比。
22. 作为登录用户，我想用我的 key 拉到的数据只缓存在我自己名下，不被其他用户看到，以便符合数据商的条款。
23. 作为用户，我想同一份公开数据（EDGAR、FRED 等）第二次请求时明显更快，以便不重复等待。
24. 作为用户，我想在数据源暂时不可用时看到"数据源暂时不可用，请稍后重试"，以便区分是我的问题还是对方的问题。
25. 作为访客，我想演示数据集里有几只"性格"不同的虚构标的（如低波动蓝筹、高波动成长、与基准高相关、带一次崩盘），以便每个指标都能看出差异。

### P6 Options Calculator

26. 作为访客，我想输入标的价格、行权价、到期时间、波动率、无风险利率和股息率，看到欧式看涨和看跌的 Black-Scholes 价格，以便快速给期权估价。
27. 作为访客，我想同时看到 Delta、Gamma、Vega、Theta、Rho，以便了解期权的敏感性。
28. 作为访客，我想输入一个市场价格，反推出隐含波动率，以便判断期权贵还是便宜。
29. 作为访客，我想看到到期 payoff 图和当前理论价值曲线，以便直观理解盈亏。
30. 作为访客，我想组合多条腿（如牛市价差、跨式、铁鹰），看组合的 payoff 和合计 Greeks，以便分析策略。
31. 作为访客，我想看 Greeks 随标的价格或到期时间变化的曲线，以便理解风险如何变化。
32. 作为访客，我想用二叉树给美式期权定价，并与 BS 结果对比，以便理解提前行权的价值。

### P3 Risk & Performance

33. 作为访客，我想选择若干标的和一个基准、一个日期区间，看到年化收益、年化波动率和最大回撤，以便快速比较风险。
34. 作为访客，我想看到历史、参数和 Cornish-Fisher 三种 VaR 与 CVaR，并能调置信水平，以便估计尾部损失。
35. 作为访客，我想看到 Sharpe、Sortino、Treynor、Information Ratio，以便比较风险调整后的收益。
36. 作为访客，我想看到相对基准的 Beta、CAPM alpha、上行和下行捕获率，以便了解标的和市场的关系。
37. 作为访客，我想选择日、周、月、季、年不同的统计周期，以便在不同尺度上看指标。
38. 作为访客，我想看滚动窗口的波动率、Beta、Sharpe 曲线，以便看到指标随时间的变化。
39. 作为访客，我想看到回撤曲线（underwater chart）并标出最大回撤的起止，以便理解最坏的时段。
40. 作为访客，我想看收益分布的直方图、偏度和峰度，以便判断是否厚尾。
41. 作为访客，我想看 VaR 回测（突破次数与 Kupiec 检验结果），以便知道 VaR 模型是否可靠。
42. 作为访客，我想看 GARCH(1,1) 的条件波动率，以便看到波动聚集。
43. 作为访客，我想看 Fama-French 三因子和 Carhart 四因子的回归结果，以便知道收益来自哪些因子。
44. 作为访客，我想在价格图上叠加常用技术指标（均线、RSI、MACD、布林带），以便结合技术面看。
45. 作为访客，我想看标的之间的相关矩阵热力图，以便了解分散化效果。

## Implementation Decisions

### 仓库与技术栈

- 本仓库 `sextant` 是 public 的，仓库里不能有任何 key。
- 采用 monorepo，包含两部分：
  - Next.js（App Router）前端：只负责交互、图表和登录会话。
  - Python 计算服务（FastAPI + pandas/numpy/scipy）：负责全部计算和取数。原版就是 pandas 写的，参考最直接；GARCH、优化器、分布拟合等数值能力也都在 Python 生态里。
- 前端和计算服务都部署在 Vercel，Python 跑在 Fluid Compute 上（包上限 5GB）。如果某项计算超出函数时限（比如大组合回测），再单独拆成长驻服务。
- 数据库到 P4 再引入，从 Vercel Marketplace 接 Neon Postgres，存用户、组合、加密的 key、保存的假设、AI 用量和数据缓存。P4 之前的缓存用平台自带的运行时缓存或无状态做法。
- 界面英文，预留 i18n 结构。

### 分层（自下而上）

1. **数据层（DataService）**
   - 每个数据源一个适配器：EDGAR、FRED、Treasury、World Bank、ECB、Frankfurter、Tiingo、FMP、合成数据。适配器之上是统一接口，每个方法都接收一个请求上下文 `ctx`，里面带 user_id（可为空）和该用户的 key。
   - 适配器负责限速、重试和错误分类，错误分为"数据源不可用"和"无此数据"。
   - 口径统一：EDGAR 的 XBRL 标签按映射表转成统一科目名，比如 Revenue、Total Assets、Operating Cash Flow，映射写成数据文件而不是代码，对应原版的 normalization CSV。一个统一科目可以对应多个候选 XBRL 标签，按优先级取第一个有值的。
   - 缓存：key 由（数据源、数据集、规范化参数）生成。
     - 公开数据源进共享缓存，按数据集设 TTL。
     - 用户自带 key 拉到的数据只能进该用户名下的缓存，绝不进共享缓存。数据源名必须和真实提供方一致，以免把付费数据登记成公开源。这一条吸取了原版托管模式的教训。
     - 一期做整请求级缓存加 TTL；时序数据的区间覆盖增量缓存（只补拉缺口、带修订窗口）作为完整版的优化，等配额或速度成为瓶颈时再做。
2. **计算层（analytics）**
   - 按领域分包：options、risk、performance、technicals、portfolio、ratios、models、valuation、macro。
   - 全部是无状态的纯函数，输入 DataFrame 或数值，输出 DataFrame 或数值；不认识用户，也不认识数据源。
   - 单个指标的错误要隔离：缺科目或除零时，该指标返回空值并附原因，不影响同批其他指标；代码缺陷（类型错误等）照常抛出。这沿用原版 handle_errors 的分流思路，但用显式的结果对象，不用"静默返回空 Series"。
3. **API 层（FastAPI）**
   - 每个工具一组 REST 端点，入参用 pydantic 模型。返回统一的结果结构：
     - 指标值
     - 每个指标的状态（ok / missing_data / error）和原因
     - 数据来源与是否演示数据
     - 计算元数据（参数、时间、数据截止日期）
   - 这个结构同时用于前端展示和 AI 层的可追溯引用：每次计算有一个 calculation id。
4. **前端**
   - 每个工具一个路由，共享导航、页脚（免责声明和署名）、Demo 标记、错误展示、CSV 导出、URL 参数同步等组件。
5. **AI 层（二期）**
   - 服务端调用 Claude API，不使用本机 `claude -p`。
   - 计算层的端点同时以工具（tool use）的形式暴露给模型。可以选择把同一套工具再包装成一个托管 MCP 端点，这是原版 router 工具思路的简化版。
   - 数字可追溯：模型只负责叙述和选工具。回答里的数字必须引用某个 calculation id 的结果，渲染时用计算结果的真值替换或校验模型写出的数字；对不上的标红。
   - 只有登录用户可用，每人每天有额度，按用户记录调用次数和 token 用量。

### 合成数据

- 用一个确定性的生成器，同一个种子永远生成同一组数据，产出虚构标的的日线 OHLCV、分红和一个演示基准。模型用几何布朗运动，可选加跳跃、GARCH 式波动聚集和相关性结构。
- 标的用虚构代码，比如 `DEMO-A` 到 `DEMO-F`，加一个 `DEMO-MKT` 作为基准，每个都有设定好的"性格"和已知参数。不使用真实代码配假价格。
- 这些已知参数同时用作测试的标准答案。

### 登录与自带 key

- 用 Google OIDC 登录，Sextant 自己签发会话。P4 上线时引入。
- 用户的 key 用服务端密钥加密后存进 Postgres。删除账号时级联删除这个用户的 key、组合、缓存和 AI 记录。
- 只有登录用户能填 key。key 保存时先调一次数据源的轻量接口来验证。

### 合规

- EDGAR 请求头里声明的联系方式从环境变量读，不写进仓库。全局限速每秒 10 次以下。
- FRED 只用公共领域序列。取序列元数据时，notes 里带 Copyright 的一律排除。页脚显示 FRED 要求的声明："This product uses the FRED® API but is not endorsed or certified by the Federal Reserve Bank of St. Louis."
- 页脚按页面实际用到的数据源显示署名，包括 SEC、ECB、World Bank（CC BY 4.0）和 Frankfurter。
- IMF 和 OECD 一期不接。IMF 用于商业需要申请，OECD 的许可没有核实。
- 原始行情价格只展示给提供 key 的那个用户本人，不进任何公开页面或共享缓存。

### 各工具的 MVP 范围（先上线这些，其余属于完整版）

- **P6**：BS 定价、五个 Greeks、隐含波动率、单腿 payoff 图。
- **P3**：基于合成数据的年化收益、波动率、最大回撤、历史 VaR/CVaR、Sharpe/Sortino、Beta，以及回撤图。
- **P4**：用代码加权重建演示组合，看累计收益 vs 基准和组合风险指标；登录后可以手动录入持仓并保存。
- **P1**：EDGAR 取数并完成口径映射，输出标准化三大报表、五类核心比率（每类 5～10 个）和 Altman Z，支持多公司对比。
- **P2**：FCF 型 DCF、可调假设、WACC 分解，以及增长率 × 折现率的敏感性表。
- **P5**：美国四大指标（GDP、CPI、失业率、利率）、美债收益率曲线和 10Y-2Y 利差。
- **P7**：用 EDGAR frames 做基本面筛选，加上最新 SEC 申报列表。
- **P8**：一期跳过。等 P1～P7 的端点都齐了，先上线各工具的"AI Explain"，再做 AI Analyst。

## Testing Decisions

- 好的测试只测外部行为（请求进去、结果出来），不测内部函数怎么拆、用了什么中间变量。重构计算层内部时，测试不应该需要修改。
- **主测试面：计算服务的 HTTP API。** 用 pytest 加 FastAPI TestClient。测试里把 DataService 换成合成数据或录制好的 fixture，不访问网络。
  - P6：检查 put-call parity；Greeks 和有限差分数值导数一致；用 BS 价格反推隐含波动率能还原输入的波动率；二叉树步数足够多时收敛到 BS 价格。
  - P3 和 P4：拿合成数据的已知参数作标准答案，比如设定年化波动率 20%，算出来的值应在合理误差内；设定的 Beta 能被回归出来；人为注入的崩盘对应的最大回撤要正确。
  - P1 和 P2：基于录制的 EDGAR 公司数据检查比率；用手算的小样例检查 DCF。
  - P5 和 P7：基于录制的 FRED、Treasury、EDGAR 响应，检查结果结构和关键数值。
  - 错误隔离：缺少某个科目时，只有对应指标的状态是 missing_data，同批其他指标正常返回。
  - 合规行为：用户自带 key 拉到的数据不会出现在另一个用户（或匿名用户）的缓存命中里。
- **第二层：数据适配器。** 用录制的真实响应（EDGAR companyfacts、FRED、Frankfurter 等）测口径映射和解析，比如同一个统一科目在不同公司用了不同 XBRL 标签时也能正确取到，缺失时给出明确的 missing 原因。另外检查 FRED 带版权声明的序列会被排除。
- **第三层：前端。** 每个工具一条 Playwright 冒烟测试：打开页面，用默认参数提交，看到结果区域和 Demo 标记。登录、自带 key、AI 解读这些流程手动验证。
- 可选的交叉核对：开发时可以用原版 `financetoolkit` 对同一份数据跑一遍，作为某些指标的参考值。这只是参考，不进 CI，也不要求 1:1 一致。
- 参考做法：这是新仓库，没有现成测试。约定：测试按行为命名，fixture 放在测试旁边。

## Out of Scope

- 实时或日内行情、交易下单、券商账户对接。
- 付费购买行情再分发许可。
- IMF、OECD 等其余宏观数据源（原版约 40 个），以及非美国公司的财报（EDGAR 只覆盖 SEC 申报公司）。
- 原版里投入产出比低的部分：copula、CoVaR、SRISK、EVaR、SVI、风险中性密度、奇异期权、Black-Litterman、Brinson 归因、完整的计量经济模块。完整版可以按需挑选，MVP 不做。
- 区间覆盖增量缓存（列为完整版优化，见上文）。
- 原版的库 → MCP 自动生成器和无状态 OAuth MCP 网关，作为独立产品不做。P8 可能用到简化版的 MCP 端点。
- 中文界面（只预留 i18n）。

## Further Notes

- 来源：2026-11-22 的设计讨论。
- 定位：产品和展示为主，学习为辅；原版是构建参考，不追求 1:1 复刻。"独立"指从用户角度看是不同界面、不同功能，后台按需共享。
- 做到每个工具时，直接读原版对应模块的源码（如 `financetoolkit/options`、`financetoolkit/risk`、`financetoolkit/portfolio`），注意原版的已知坑：报表列是财年期间而非公布日期（日度指标要防前视偏差）、报表币种可能与上市币种不同、技术指标需要起始日之前的 lookback 数据、`Benchmark`/`Portfolio` 这类特殊列名要过滤。
- 数据源条款调研于 2026-11-22。FMP、OECD、Stooq、Massive 个人档条款和 US Treasury 的使用条款未能核实原文；接入任何新数据源前要重新确认条款。
